## 今日必看 1：AgentFloor｜小模型能不能做 Agent，今天有了分层测试

原文链接：https://arxiv.org/abs/2605.00334

### 最近发生了什么？

arXiv 上新发布了一篇 AgentFloor 论文，专门测试小型开源模型做 AI Agent 的能力。它不是发布一个新模型，而是做了一套评估体系，用来判断小模型到底能不能调用工具、完成多步任务、做长程规划。

### 以前的问题是什么？

现在很多人都在做 AI Agent，但一个关键问题一直没讲清楚：是不是所有 Agent 任务都必须用 GPT-5 这类强模型？小模型能不能承担一些简单任务？如果能，哪些任务可以交给小模型，哪些任务必须交给强模型？

### 这次新增了什么？

这篇论文设计了 30 个任务、6 层能力阶梯，测试 16 个开源模型，并和 GPT-5 做对比。它不是笼统地说“某个模型会不会做 Agent”，而是把 Agent 能力拆成不同难度层级来测。

### 人话解释

这就像给 AI Agent 做分级考试。简单题，比如按规则调用工具、完成短流程，小模型已经有机会胜任；难题，比如连续规划、记住多个约束、长时间不跑偏，小模型还是容易出错。

### 对你的影响

这条和你的 AI 新闻简报系统关系很大。你的系统每天会抓几千条信息，不需要所有环节都用强模型。更合理的是：规则先筛选，小模型做初步分类和总结，强模型只分析最重要的几条。

### 是否值得关注？

值得深读。它直接关系到你以后怎么降低 API 成本、怎么设计模型分层、怎么让自动化系统长期稳定运行。

## 今日必看 2：SAGA｜Agent 跑得慢，可能不是模型差，而是调度方式不对

原文链接：https://arxiv.org/abs/2605.00528

### 最近发生了什么？

arXiv 上出现了一篇 SAGA 论文，研究 AI Agent 在 GPU 集群上运行时该怎么调度。它关注的不是模型变聪明，而是 Agent 任务怎么跑得更快、更稳。

### 以前的问题是什么？

传统 GPU 调度通常把每次 LLM 调用当成独立请求。但 Agent 做任务不是只问模型一次，它可能要多轮思考、调用工具、读写状态、再继续推理。如果每一步都被系统当成孤立请求处理，就容易丢上下文、增加延迟、浪费资源。

### 这次新增了什么？

SAGA 提出“工作流原子调度”，把 Agent 的整个执行过程看成一个整体，而不是一堆散开的模型请求。它通过 Agent 执行图、会话亲和批处理等机制，提高 Agent 推理效率。

### 人话解释

以前像是每次只安排一个工人干一小步，干完就散；SAGA 更像是把整个项目当成一条流水线来安排，知道前后步骤之间有关联，所以调度更顺。

### 对你的影响

这能帮你理解 n8n 的意义。n8n 在你个人自动化里也扮演类似角色：不是模型本身，而是负责把抓取、筛选、总结、写入 Notion、推送这些步骤串起来。模型负责思考，工作流系统负责让事情按顺序跑完。

### 是否值得关注？

值得略读。如果你关注 AI Agent、n8n、GitHub Actions、自动化调度，这条有启发；但它偏底层 GPU 集群，不需要你现在深挖全部技术细节。

## 今日必看 3：Agent Factories｜编码 Agent 开始进入硬件优化，不只是写网页

原文链接：https://arxiv.org/abs/2603.25719

### 最近发生了什么？

研究者开始把通用编码 Agent 用到硬件优化里，而不只是让它写普通软件代码。论文里使用 Claude Code 这类编码 Agent，尝试优化高层综合硬件设计，并在部分基准上取得明显加速。

### 以前的问题是什么？

以前大家理解 coding agent，主要是写网页、改脚本、修 bug、补测试。但硬件优化、芯片相关设计、HLS 这类任务更专业，过去通常认为需要很强的领域工程经验，不是普通 coding agent 能轻易处理的。

### 这次新增了什么？

这篇论文提出了两阶段 Agent 工厂流水线，让多个编码 Agent 一起尝试优化硬件设计。它在 12 个基准测试上，从 1 个 Agent 扩展到 10 个 Agent 后，平均带来 8 倍以上加速。

### 人话解释

这说明编码 Agent 正在从“帮程序员写代码”，进入“帮工程师做专业优化”的阶段。它不再只是写个网页，而是开始碰硬件设计、性能优化、工程搜索这类更专业的东西。

### 对你的影响

这条和你的半导体背景有关系。未来半导体、硬件、EDA、测试、仿真这些环节，可能都会慢慢引入 Agent 辅助。你如果既懂行业，又懂怎么让 Agent 进入工作流，会比只懂普通销售或只会简单问 AI 更有优势。

### 是否值得关注？

值得深读。它和“AI 如何进入半导体 / 硬件工程”有关，对你的职业判断有价值。

## 今日必看 4：A11y-Compressor｜让 GUI Agent 看屏幕更省 token、更有效率

原文链接：https://arxiv.org/abs/2605.00551

### 最近发生了什么？

arXiv 上出现了一篇 A11y-Compressor 论文，研究如何让 GUI Agent 更高效地理解电脑界面。它主要处理的是“AI 看屏幕时，输入信息太长、太乱、太费 token”的问题。

### 以前的问题是什么？

如果 AI 要操作网页、软件、按钮、输入框，它需要理解界面结构。常见做法是读取“可访问性树”，也就是界面元素的结构描述。但这个结构往往很长、重复信息多、空间关系不清楚，导致模型读起来费 token，成功率还不稳定。

### 这次新增了什么？

A11y-Compressor 把线性化的可访问性树压缩成更紧凑、更结构化的表示。论文里提到，它能明显减少输入 token，同时提升 GUI Agent 的任务成功率。

### 人话解释

就像你让一个人看一张混乱的说明书，他很难操作机器；如果你把说明书整理成清晰的按钮、区域、步骤，他就更容易做对。A11y-Compressor 做的就是把 AI 看到的界面信息整理得更干净。

### 对你的影响

这和你之前说的“希望 AI 能直接操作工具”很相关。未来 ChatGPT、Codex、浏览器 Agent、电脑操作 Agent 要真正好用，不只是模型要强，还要让模型看到的信息更清楚、更省 token。

### 是否值得关注？

值得略读。它不一定马上影响你的新闻简报系统，但和未来 AI 操作 GitHub、Notion、网页、软件界面有关。

### AutoMat｜编码 Agent 复现科研论文，目前还不太稳

原文链接：https://arxiv.org/abs/2605.00803

这条新闻的重点不是“AI 又更强了”，而是提醒我们：AI 会写代码，不代表它能完整理解并复现专业科研。科研复现需要理解论文、补全流程、调用专业工具链、判断结果是否支持结论。当前 Agent 在这类专业科学工作流里仍然有限。

**对你最重要的启发：**你的 AI 新闻简报系统必须继续保留原始链接、来源等级和验证状态。AI 摘要只能帮助快速理解，不能当最终事实。

---

### ExCyTIn-Bench｜Agent 开始进入网络安全调查

原文链接：https://arxiv.org/abs/2507.14201

这条新闻说明，Agent 正在进入“查线索、看日志、做调查”的专业场景。网络安全调查信息量大、线索多，适合让 Agent 做初步整理，再由人判断。

**对你的启发：**你的新闻简报系统本质上也是类似工作：从大量信息里筛重点。未来可以让 Agent 先帮你做线索整理，但最后判断仍要你自己确认。

---

### AGoQ｜AI 训练正在追求更省显存、更低成本

原文链接：https://arxiv.org/abs/2605.00539

这条新闻讲的是训练大模型时怎么省显存。AGoQ 通过激活量化和梯度量化，让训练更省资源。

**对你的启发：**AI 行业不只是追求模型更大，也在追求更便宜、更快、更省显存。你的自动化系统也应该这样设计：低价值信息用规则过滤，中等价值信息用便宜模型总结，高价值信息再交给强模型分析。

---

### LightKV｜多模态模型也在压缩缓存，目标是推理更便宜

原文链接：https://arxiv.org/abs/2605.00789

LightKV 研究的是视觉大模型的 KV Cache 压缩。简单说，就是模型看图片时会产生很多视觉 token，LightKV 想办法只保留关键部分，减少显存和计算量。

**对你的启发：**未来你让 AI 看截图、看 PPT、看网页、看图纸时，视觉 token 成本会很关键。多模态 AI 也在往“更低成本、更实用”方向发展。

## 今日总判断

今天这组新闻说明：AI Agent 正在进入工程化阶段。

第一，AgentFloor 在回答“小模型能不能做 Agent”。结论是：简单任务可以考虑小模型，复杂长任务仍然需要强模型。

第二，SAGA 和 A11y-Compressor 在回答“Agent 怎么跑得更稳、更快”。这说明 Agent 系统不只是模型能力问题，还包括调度、输入压缩、界面信息整理。

第三，Agent Factories、AutoMat、ExCyTIn-Bench 在说明：Agent 正在进入硬件优化、科研复现、安全调查这些专业领域，但还不能完全替代专业人。

第四，AGoQ、LightKV、llama.cpp 更新说明：未来 AI 竞争会越来越重视成本、显存、缓存、本地推理和工具调用稳定性。
