**1. AgentFloor：小开源模型在工具使用阶梯上能走多远？**
[1. AgentFloor：小开源模型在工具使用阶梯上能走多远？](https://arxiv.org/abs/2605.00334)
- **背景与问题**：当前 Agent 能力评估多集中在 GPT-4、Claude 等大型闭源模型上。小尺寸的开源模型（如 7B、13B 参数）在工具使用（Tool Use）方面的能力上限尚不明确。
- **这次发生了什么**：研究者提出了 AgentFloor 基准，旨在系统性地评估小开源模型在“工具使用阶梯”上的表现。这个阶梯可能包含从简单工具调用到复杂多步骤工作流的不同层级。
- **具体变化与结果**：原文未给出具体的模型排名或量化结果。该基准的设计本身是本次的贡献。
- **为什么重要**：对于希望使用本地、低成本模型构建 Agent 的开发者，了解小模型的能力边界至关重要。AgentFloor 提供了一个评估框架。
- **建议动作**：暂时观察。该基准可以帮助你判断哪些小模型适合你的 Agent 任务。

**2. SAGA：面向 AI Agent 推理的工作流原子调度方案**
[2. SAGA：面向AI Agent推理的工作流原子调度方案](https://arxiv.org/abs/2605.00528)
- **背景与问题**：AI Agent 在执行复杂任务时，通常需要调用多个模型（如 LLM、视觉模型）并执行多个步骤，形成一个工作流。在 GPU 集群上调度这些工作流时，如何保证效率、避免资源碎片化是一个难题。
- **这次发生了什么**：研究者提出了 SAGA，一种“工作流原子”调度方案。它将整个 Agent 工作流视为一个不可分割的原子任务进行调度，而不是将其拆解成独立的模型调用。
- **具体变化与结果**：原文未给出具体的性能提升数据。该方案的核心思想是优化工作流级别的调度，而非单次推理的调度。
- **为什么重要**：随着 Agent 工作流越来越复杂，传统的单次推理调度器可能成为瓶颈。SAGA 代表了调度优化的新方向。
- **建议动作**：暂时观察。这是一个面向基础设施层的优化研究，对于普通开发者来说，了解其概念即可。

[3. Agent Factories：通用编码代理在高层综合硬件优化中取得8倍加速](https://arxiv.org/abs/2603.25719)

[12. vLLM v0.20.1 发布：聚焦 DeepSeek V4 稳定性和性能改进](https://github.com/vllm-project/vllm/releases/tag/v0.20.1)
- **背景与项目**：vLLM 是一个高性能、内存高效的大模型推理和服务引擎，广泛应用于生产环境。
- **这次发生了什么**：vLLM 发布了 v0.20.1 补丁版本，主要针对 DeepSeek V4 模型进行稳定性和性能改进。
- **具体变化**：
    - **性能优化**：引入了多流预注意力 GEMM（通用矩阵乘法）并优化了默认阈值；支持 BF16 和 MXFP8 格式的 all-to-all 通信；集成了优化的 tile 内核用于头部计算。

**2. llama.cpp 多版本发布（b9019 - b9025）**
llama.cpp 是一个用 C/C++ 实现的高性能大模型推理库，支持在本地 CPU 和 GPU 上运行。今日发布了多个版本，主要涉及架构重构和功能修复。
- **b9025**：将 KleidiAI（一个针对 ARM CPU 的 AI 加速库）更新至 v1.24.0，并改用 Release Archive 方式分发。这对于在 Apple Silicon Mac 上运行的用户是性能提升。

## 算力 / 半导体观察

**1. LightKV：利用 prompt 引导压缩视觉 token KV 缓存，仅用 55% token 性能不变**
[6. LightKV：利用 prompt 引导压缩视觉 token KV 缓存，仅用55% token 性能不变](https://arxiv.org/abs/2605.00789)
- **背景与问题**：多模态大模型（LVLM，如 GPT-4V）在处理图像时，会将图像切分成大量视觉 token（词元）。这些 token 的 KV 缓存（Key-Value Cache）在推理时会消耗巨大的显存，成为性能瓶颈。
- **这次发生了什么**：研究者提出了 LightKV 方法，利用用户输入的 prompt（提示词）来引导压缩视觉 token 的 KV 缓存。它只保留与 prompt 最相关的视觉信息。
- **具体变化与结果**：实验表明，LightKV 仅使用 **55%** 的原始视觉 token，就能保持模型性能不变。这直接意味着推理显存占用降低近一半。
- **为什么重要**：这属于推理优化技术，位于算力链条的“推理”环节。对于部署多模态模型的服务商，这意味着可以用更少的 GPU 服务更多用户，或支持更高分辨率的图像输入。
- **建议动作**：归档关注。这是一个有潜力的优化方向，未来可能被集成到 vLLM 等推理框架中。

**2. AGoQ 实现 4 位激活与 8 位梯度量化，LLaMA 训练内存节省 52%**
[11. AGoQ 实现 4 位激活与 8 位梯度量化，LLaMA 训练内存节省 52%](https://arxiv.org/abs/2605.00539)
- **背景与问题**：训练大型语言模型（LLM）需要巨大的显存，其中大部分被激活值（Activations）和梯度（Gradients）占据。传统的训练通常使用 16 位或 32 位浮点数。
- **这次发生了什么**：研究者提出了 AGoQ，一种用于分布式训练的激活和梯度量化方法。它将激活值量化为 4 位，梯度量化为 8 位。
- **具体变化与结果**：在 LLaMA 模型上的实验显示，AGoQ 可以节省 **52%** 的训练内存，同时保持模型精度几乎不受影响。
- **为什么重要**：这属于训练优化技术，位于算力链条的“训练”环节。对于需要自己训练或微调大模型的团队，这意味着可以用更少的 GPU 资源完成训练，或训练更大的模型。
- **建议动作**：归档关注。这是一个重要的训练优化研究，未来可能被集成到 DeepSpeed、Megatron 等分布式训练框架中。

## 今日建议动作
1.  **立即检查**：如果你的团队正在开发或使用医疗、金融等领域的 RAG 聊天机器人，请立即进行安全审查，特别是后端 API 的访问控制和数据隔离。参考 [18. 医疗 RAG 聊天机器人被曝后端漏洞](https://arxiv.org/abs/2605.00796)。
2.  **建议升级**：如果你的生产环境使用 vLLM 部署了 DeepSeek V4 模型，请尽快测试并升级到 v0.20.1 版本，以获得稳定性和性能改进。参考 [12. vLLM v0.20.1 发布](https://github.com/vllm-project/vllm/releases/tag/v0.20.1)。
3.  **归档关注**：
    - 关注 `LightKV` 和 `AGoQ` 两项研究，它们分别代表了推理和训练阶段的显存优化方向，未来可能被主流框架集成。
    - 关注 `Agent Factories` 和 `ExCyTIn-Bench`，它们分别展示了 Agent 在硬件设计和网络安全领域的应用潜力。
4.  **暂时观察**：
    - `AgentFloor`、`SAGA`、`A11y-Compressor`、`AutoMat`、`MathArena`、`CA-ThinkFlow` 和 `NorBERTo` 均为研究项目，距离产品化还有距离，适合作为知识储备。
    - llama.cpp 的多个版本更新（b9019-b9025）主要为开发者和高级用户准备，普通用户可暂时观察，等待更稳定的版本。
