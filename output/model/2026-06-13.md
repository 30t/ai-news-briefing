## Agent / 编程工具趋势

### NVIDIA Blackwell 在首个 Agentic AI 基础设施基准测试 AgentPerf 中大幅领先
[4. NVIDIA Blackwell在首个Agentic AI基础设施基准测试AgentPerf中领先](https://blogs.nvidia.com/blog/nvidia-blackwell-agentperf-artificial-analysis)

**背景**：Agentic AI（能自主分解任务、调用工具、多步推理的 AI 系统）的工作负载与传统的对话式 AI 完全不同。一次对话只是一次 LLM 调用，而一个 Agent 任务可能涉及数十到数百次链式 LLM 调用，每次调用之间还要执行代码编译、数据库查询、网页浏览等工具调用，上下文不断累积，复杂度是指数级增长的。现有的 AI 推理基准测试（如测量单次 LLM 响应速度或并发请求数）无法反映这种真实压力。

**这次发生了什么**：行业分析机构 Artificial Analysis 发布了首个专门针对 Agentic AI 基础设施的基准测试 **AgentPerf**。首轮结果中，**NVIDIA Blackwell Ultra NVL72 平台**在所有测试的 Agentic AI 工作负载上表现领先，**每兆瓦功耗可运行的 Agent 数量是上一代 Hopper 平台的 20 倍**。

**为什么重要**：这是业界首次为 Agentic AI 基础设施提供标准化的性能对比方法。对于正在评估和部署 Agent 系统的企业来说，AgentPerf 的结果直接影响了硬件选型和成本效益分析。它表明，为对话式 AI 优化的硬件不一定适合 Agent 工作负载，而 Blackwell 架构在应对链式调用和上下文累积方面具有显著优势。

**建议动作**：如果你正在规划 Agent 系统的生产部署，建议关注 AgentPerf 的后续更新，并将“每瓦特 Agent 吞吐量”纳入硬件选型的关键指标。

### 两篇 arXiv 论文聚焦 OS-Agent 评估：ISE 与 Workflow-GYM
今日有两篇来自 arXiv 的早期研究论文，分别提出了新的 Agent 训练数据生成方法和长周期评估基准。**请注意：这些是研究信号，不等于已经产品化。**

- **[5. ISE: An Execution-Grounded Recipe for Multi-Turn OS-Agent Trajectories](https://arxiv.org/abs/2606.11520)**：这篇论文提出了一种名为 ISE 的方法，用于生成“以执行为基础”的多轮操作系统 Agent 轨迹数据。简单来说，它试图解决 Agent 训练数据不足且质量不高的问题，通过让 Agent 在真实操作系统中执行任务来生成更可靠的训练数据。这对提升 OS-Agent（如能操控电脑完成任务的 AI）的实用性有潜在价值。

- **[6. Workflow-GYM: Towards Long-Horizon Evaluation of Computer-use Agentic tasks in Real-World Professional Fields](https://arxiv.org/abs/2606.11042)**：这篇论文提出了 Workflow-GYM，一个用于评估计算机使用 Agent 在真实专业领域（如数据分析、文档处理）中完成长周期任务能力的基准。与现有基准相比，它更强调任务的长期性和专业性，试图更真实地反映 Agent 在实际工作中的表现。

**建议动作**：对 Agent 训练和评估感兴趣的研究者可以关注这两篇论文的代码和数据发布。普通开发者暂时无需采取行动，但可以留意后续是否有基于这些研究的开源工具出现。

## 开源项目 Release 汇总

### vLLM v0.23.0：DeepSeek-V4 多后端成熟，MRv2 默认支持 Llama/Mistral
[7. vLLM v0.23.0 发布：DeepSeek-V4 多后端成熟，MRv2 默认支持 Llama/Mistral](https://github.com/vllm-project/vllm/releases/tag/v0.23.0)

**背景**：vLLM 是目前最流行的高性能大模型推理服务框架之一，被大量企业和开发者用于部署 LLM 服务。它通过 PagedAttention 等技术显著提升了推理吞吐量。

**这次发生了什么**：vLLM v0.23.0 正式发布，包含 408 次提交和 200 位贡献者的工作。主要亮点包括：
1. **DeepSeek-V4 多后端成熟**：继 v0.22.0 引入后，本次对 DeepSeek-V4 进行了大规模加固和优化。其稀疏 MLA（Multi-head Latent Attention）元数据已与 DeepSeek-V3.2 解耦，并新增了 TRTLLM-gen 注意力内核、EPLB（Expert Parallel Load Balancing）支持、选择性前缀缓存保留等功能。模型还从 `torch.compile` 中解耦，并重构了注意力和 RoPE（旋转位置编码）路径。
2. **Model Runner V2 默认支持更多密集模型**：MRv2 现在默认用于 **Llama 和 Mistral 密集模型**（此前已默认用于 Qwen3）。它新增了 FlashInfer 采样器、可中断 CUDA 图、流水线并行气泡消除等特性，可进一步提升推理效率。
3. **其他改进**：包括对 MiniMax-M3 的初步支持（但尚未完全就绪）、新的 `vllm serve` 命令、以及多项性能优化和 bug 修复。

**为什么重要**：vLLM 是 AI 推理部署的关键基础设施。本次更新显著提升了 DeepSeek-V4（一个重要的开源 MoE 模型）和 Llama/Mistral 等主流密集模型的推理效率，对使用 vLLM 的开发者具有直接价值。

**建议动作**：如果你正在使用 vLLM 部署 DeepSeek-V4、Llama 或 Mistral 模型，建议升级到 v0.23.0 以获取性能提升和 bug 修复。升级前请查阅完整的 Release Notes，特别是关于 MiniMax-M3 尚未完全支持的说明。

### llama.cpp b9606：新增 EAGLE3 投机解码支持
[1. llama.cpp b9606：新增 EAGLE3 投机解码支持](https://github.com/ggml-org/llama.cpp/releases/tag/b9606)

**背景**：llama.cpp 是一个用 C/C++ 编写的高性能大模型推理库，专注于在消费级硬件（CPU、GPU）上高效运行 LLM。投机解码（Speculative Decoding）是一种加速推理的技术，通过使用一个轻量级的“草稿模型”来预测主模型的输出，从而减少主模型的调用次数。

**这次发生了什么**：llama.cpp b9606 版本新增了对 **EAGLE3 投机解码**的支持。EAGLE3 是一种较新的投机解码方法，相比前代可能具有更高的加速比。本次更新包括层输入提取、参数修复、多序列处理等改进，并适配了 Gemma4 等模型架构。

**为什么重要**：对于使用 llama.cpp 在本地运行大模型的开发者来说，EAGLE3 支持可以显著提升推理速度，尤其是在资源受限的设备上。这是一个重要的性能升级。

**建议动作**：如果你使用 llama.cpp 进行本地推理，建议升级到 b9606 版本，并尝试启用 EAGLE3 投机解码以测试加速效果。原文未给出具体的量化加速比，建议自行测试。

### CrewAI 1.14.7：可插拔后端、对话 API 与 Snowflake Cortex 支持
[2. CrewAI 1.14.7 发布：可插拔后端、对话 API 与 Snowflake Cortex 支持](https://github.com/crewAIInc/crewAI/releases/tag/1.14.7)

**背景**：CrewAI 是一个用于编排多 Agent 协作工作流的开源框架，允许开发者定义多个具有不同角色和工具的 Agent，让它们协同完成任务。

**这次发生了什么**：CrewAI 1.14.7 发布，主要新特性包括：
1. **可插拔默认后端**：为内存、知识库、RAG（检索增强生成）和流程提供了可插拔的默认后端，降低了自定义集成的门槛。
2. **对话 API**：新增了用于对话式流程的聊天 API，使得构建交互式 Agent 应用更加方便。
3. **原生 Snowflake Cortex LLM 提供程序**：可以直接使用 Snowflake Cortex 平台上的 LLM 作为 CrewAI 的模型后端。
4. **其他改进**：包括路由感知的 DSL 触发器装饰器、修复了检查点恢复、并发隔离、文件输入可靠性等多个问题。

**为什么重要**：可插拔后端和对话 API 使得 CrewAI 更加灵活和易用，Snowflake Cortex 支持则扩展了其 LLM 选项。对于使用 CrewAI 构建 Agent 工作流的开发者来说，这是一个值得升级的版本。

**建议动作**：如果你正在使用 CrewAI，建议升级到 1.14.7 以利用新特性和 bug 修复。特别是如果你需要集成自定义后端或使用 Snowflake Cortex 模型，这个版本会很有帮助。

### Ollama v0.30.8：修复 provider 选择错误，改进 prompt caching 与 MLX 稳定性
[3. Ollama v0.30.8 发布：修复 provider 选择错误，改进 prompt caching 与 MLX 稳定性](https://github.com/ollama/ollama/releases/tag/v0.30.8)

**背景**：Ollama 是一个让用户能在本地轻松运行大模型的开源工具，它封装了模型下载、推理和 API 服务，深受个人开发者和爱好者喜爱。

**这次发生了什么**：Ollama v0.30.8 是一个修复和改进版本，主要变化包括：
1. **修复了 `ollama launch` 在某些情况下选择错误 provider 的问题**：这解决了影响启动的 bug。
2. **改进了 prompt caching**：将 prompt caching 与 context shift 解耦，以提升 KV 缓存复用效率，从而加快重复请求的响应速度。
3. **增强了 MLX 推理的稳定性**：MLX 是 Apple 的机器学习框架，用于在 Apple Silicon 芯片上高效运行模型。本次更新硬化了线性层和嵌入层，并在 prompt 处理和推测解码时创建快照，提升了可靠性。
4. **改进了循环模型支持**：通过来自门控 delta 内核的每边界状态，改进了对循环模型的支持。

**为什么重要**：对于使用 Ollama 进行本地推理的用户，此版本修复了影响启动的 bug，并提升了缓存效率和 MLX 后端的可靠性。如果你在 Apple Silicon Mac 上使用 Ollama，MLX 的稳定性改进尤其值得关注。

**建议动作**：建议所有 Ollama 用户升级到 v0.30.8。如果你在 Apple Silicon 设备上运行模型，升级后可以测试 MLX 后端的稳定性是否有所改善。
