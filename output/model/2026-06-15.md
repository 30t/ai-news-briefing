## 工具链更新汇总

**OpenRouter 低成本推理指南**：OpenRouter 发布了一篇实用教程，教你如何获得最低成本的 LLM 推理。核心技巧包括：在模型 slug 后追加 `:floor` 自动路由到最便宜的提供商、使用 `max_price` 设置硬预算上限、以及利用 20 多个免费模型（免费账户每天 50 次请求，充值 10 美元后提升至每天 1000 次）。原文还提醒了计费陷阱，例如不同提供商对同一模型的定价可能相差数倍。对于正在搭建 AI 应用、需要控制推理成本的开发者，这是一份值得收藏的配置手册。[12. 如何在OpenRouter上获得最低成本的LLM推理](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter)

**KPMG 因 AI 幻觉撤回报告**：专业服务公司 KPMG 发布了一份名为“在 Agentic AI 时代重新定义卓越”的报告，随后被多家机构指出内容不实。UBS、英国 NHS、瑞士联邦铁路和伦敦交通局均表示报告中对它们 AI 使用情况的描述“不真实或具有误导性”。研究机构 GPTZero 认定这些不准确内容源于 AI 幻觉——KPMG 很可能用 AI 辅助撰写了一份关于 AI 的报告。KPMG 已撤回报告并展开内部调查。这是继上月 EY 因虚假脚注撤回报告后的又一起事件，凸显了企业级 AI 应用在文档生成和审计中的严重风险。[16. KPMG因AI幻觉撤回报告：企业AI应用可信度再受质疑](https://techcrunch.com/2026/06/13/kpmg-pulls-report-on-ai-usage-due-to-apparent-hallucinations)

**英国警察因使用 AI 伪造证据被调查**：英国德比郡一名警察被调查，涉嫌在多个案件中使用 AI 生成虚假证据。这一事件引发了关于 AI 在司法系统中滥用风险的严重担忧，可能推动更严格的 AI 监管政策，并影响 AI 产品的合规设计。[17. 英国警察因使用AI伪造多起案件证据被调查](https://news.sky.com/story/derbyshire-police-officer-investigated-for-using-ai-to-create-evidence-in-multiple-cases-13553661)

## Agent / 编程工具趋势

**Meta 据报应北京要求撤销 2 亿美元 Manus 收购交易**：TechCrunch 报道称，Meta 已开始解除对 AI Agent 初创公司 Manus 的 2 亿美元收购。具体措施包括切断 Manus 与 Meta 内部系统的连接、停止数据共享，这是对北京约两个月前以国家安全为由发布的撤资令的最具体回应。与此同时，Manus 联合创始人已初步讨论从外部投资者处筹集约 10 亿美元以从 Meta 手中回购公司，可能为组建中国合资企业并在香港上市铺路。该事件凸显了 AI Agent 领域跨境并购的地缘政治风险，对关注 AI 商业化和 Agent 生态的读者有重要跟踪价值。[1. Meta据报应北京要求撤销2亿美元Manus收购交易](https://techcrunch.com/2026/06/13/meta-reportedly-moves-to-unwind-2b-manus-deal-after-beijings-demand)

**ACM CAIS 2026 论文提出“验证税”概念**：一篇发表于 ACM CAIS 2026 的论文研究了工具使用 LLM Agent 的安全评估问题。核心发现是：任务完成率本身具有误导性——Agent 可能在完成任务的同时违反安全或策略约束。研究者将结果分为安全成功、不安全成功和失败三类，并提出两级验证架构（确定性策略检查 + LLM 验证器）。主要发现是：验证可以减少不安全成功，但随着任务长度增加，也会降低任务完成率，形成所谓的“验证税”（Verifier Tax）。该研究揭示了 Agent 安全评估中的一个关键权衡，对设计更可靠的 Agent 系统有指导意义。**社区讨论，不等于官方确认**。[2. ACM CAIS 2026论文提出'验证税'：工具使用LLM智能体的安全-成功权衡随任务长度变化](https://www.reddit.com/r/MachineLearning/comments/1u58mkq/the_verifier_tax_horizondependent_safetysuccess)

**AI 早报：编程瓶颈从模型转向人、Agent 确定性规划模式全景**：本期早报包含多条关键信息：阿里工程师总结 AI 编程半年经验，指出瓶颈已从模型能力转向人的注意力；Spring I/O 视频详解 Agent 确定性规划模式；Mastra vs LangChain 对比分析；Codex 浏览器操作模式选型指南等。对于正在使用 AI 编程工具的开发者，这些内容有助于理解当前工作流中的真实瓶颈和工具选型方向。[6. **OpenAI 模型和 Codex 可通过 Oracle 云承诺访问**：OpenAI 宣布，用户可以通过 Oracle 云的现有承诺来访问 OpenAI 模型和 Codex（OpenAI 的 AI 编程 Agent），利用企业级安全性和治理能力进行构建和部署。这对于已有 Oracle 云承诺的企业用户来说，是一个降低 AI 工具部署门槛的信号。[9. Access OpenAI models and Codex through your Oracle cloud commitment](https://openai.com/index/openai-on-oracle-cloud)

**macOS 本地编程 Agent 搭建指南**：一位开发者分享了在 macOS 上搭建本地编程 Agent 的完整教程。他使用 llama.cpp 配合 Metal 加速，运行 Gemma 4 26B-A4B 和 Qwen3.6 35B-A3B 模型，并利用 MTP（多 Token 预测）投机解码技术提升速度。在 Apple M1 Max（64GB 统一内存）上，主模型推理速度约 58 tokens/秒，配合 MTP 草稿模型后速度进一步提升。该指南对于希望摆脱网络依赖、在本地运行编程 Agent 的 Mac 用户有直接参考价值。**社区分享，测试条件为特定硬件环境，结果可能因配置不同而异**。[10. How to setup a local coding agent on macOS](https://ikyle.me/blog/2026/how-to-setup-a-local-coding-agent-on-macos)

**datasette-agent 0.2a0：Agent 可向用户提问**：Simon Willison 发布了 datasette-agent 0.2a0 版本，这是一个为 Datasette（一个开源的多维数据探索工具）打造的 LLM 驱动 Agent。新版本引入了 `ask_user()` 功能，允许 Agent 在执行过程中向用户提问（支持是/否、多选或自由文本）。问题未回答时 Agent 暂停，答案会持久化到内部数据库，即使服务器重启也能恢复。此外，新增了 `save_query` 工具，Agent 可以将编写的 SQL 保存为 Datasette 存储查询，但保存前必须获得人工批准。该版本为 alpha 预发布版本，更适合开发者测试，不一定适合生产环境。[13. datasette-agent 0.2a0](https://simonwillison.net/2026/Jun/10/datasette-agent)

## 开源项目 Release 汇总

**Ollama v0.30.8**：Ollama（本地运行大模型的开源工具）发布了 v0.30.8 版本。主要修复包括：修复了 `ollama launch` 在某些情况下选择错误提供商的问题；改进了提示缓存（Prompt Caching），将其与上下文切换解耦以实现更好的 KV 缓存复用；增强了 MLX（Apple 芯片上的机器学习框架）推理的稳定性，加固了线性和嵌入层；MLX 运行器现在在提示处理和投机解码期间创建快照以提高可靠性；改进了循环模型支持。原文未明确说明从哪个版本升级而来。对于 Ollama 用户，建议升级以获得更稳定的本地推理体验。[3. Ollama v0.30.8：* Fixed `ollama launch` selecting the wrong provider in some cases](https://github.com/ollama/ollama/releases/tag/v0.30.8)

**llama.cpp b9626：新增 cohere2-MoE 架构支持**：llama.cpp（高性能大模型推理框架）发布了 b9626 版本。本次更新主要增加了对 cohere2-MoE（Cohere 公司的混合专家模型架构）的架构支持。具体改动包括：重命名架构为 cohere2moe、修复了 `first_k_dense_replace` 错误、改进了共享专家平均计算方式、修复了 MTP（多 Token 预测）失败问题等。对于需要在本地运行 Cohere 系列模型的用户，这是一个值得关注的更新。原文未明确说明从哪个版本升级而来。[5. llama.cpp b9626：Add arch support for cohere2-MoE (#24260)](https://github.com/ggml-org/llama.cpp/releases/tag/b9626)

**Pyodide 314.0：Python WASM wheels 可直接发布到 PyPI**：Pyodide（在浏览器中运行 Python 的开源项目）发布了 314.0 版本。核心更新是：现在可以将为 Pyodide 编译的 Python 包（WASM wheels）直接发布到 PyPI，并在运行时安装。此前，Pyodide 维护者需要手动维护、构建和托管超过 300 个包，成为社区的主要瓶颈。现在，包维护者可以像发布 Linux、macOS 或 Windows 的原生 wheels 一样，将 Pyodide wheels 发布到 PyPI。这大大降低了 Python 在浏览器中运行的门槛，对 Web 端 AI 应用、数据分析和工具链部署有直接推动作用。[11. Pyodide 314.0 发布：Python WASM wheels 可直接发布到 PyPI，简化浏览器端包分发](https://simonwillison.net/2026/Jun/13/publishing-wasm-wheels)
