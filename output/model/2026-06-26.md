## 工具链更新汇总

### Claude Tag：在 Slack 中通过 @Claude 协作

**背景：** Anthropic 是 Claude 模型的开发公司。此前 Claude 主要通过对话界面（Claude Code、Cowork）与用户交互，属于“你问它答”或“单次任务”模式。

**这次发生了什么：** Anthropic 推出了 [15. Claude Tag](https://www.anthropic.com/news/introducing-claude-tag)，一种全新的协作方式。Claude 可以像团队成员一样加入 Slack 频道，任何人在频道中 @Claude 即可委托任务。Claude 能记住频道上下文，支持多用户交互，经授权后可自动学习其他频道和数据源。开启“环境感知”行为后，它还能主动更新未解决的线程或任务，并支持异步工作数小时或数天。

**具体变化：**
- 不再是单次对话，而是持续参与的团队协作者。
- 支持异步推进：交给 Claude 一个任务后，用户可以专注于其他工作。
- 管理员可精细控制工具和渠道访问权限、设置 token 消耗限额，并查看所有操作日志。

**结果或证据：** Anthropic 内部数据显示，其产品团队 65% 的代码已由内部版本的 Claude Tag 生成。该模式已扩展到工程以外的领域，如追踪产品指标、处理支持工单、查找 Bug 根因。

**为什么重要：** Claude Tag 把 AI 从“工具”变成了“队友”，改变了团队协作的工作流。对于使用 Slack 的企业团队，这意味着 AI 可以更自然地融入日常沟通和任务管理。

**建议动作：** 如果你是 Claude Enterprise 或 Team 客户，可以立即申请 beta 版试用。其他用户可关注后续扩展计划。

> 注：本文基于 Anthropic 官方公告和 AIHOT Featured 的报道，两者内容一致，均指向同一事件。

### 提示注入的机制解释

**背景：** 提示注入（Prompt Injection）是 LLM 应用中的常见安全漏洞，攻击者通过恶意输入让模型忽略原始指令。

**这次发生了什么：** [18. 提示注入的机制解释（以及为什么你应该研究角色）— LessWrong](https://www.bestblogs.dev/en/article/8f187d0e?entry=rss_article_item) 发表了一篇技术分析文章，从机制层面解释提示注入的原因：LLM 无法通过标签感知角色（如系统角色、用户角色），而是依赖写作风格来区分，这使得攻击者可以通过模仿风格（如 CoT Forgery）实施攻击。

**为什么重要：** 这篇分析对 Agent 和工具链开发者有直接参考价值——理解注入的底层机制有助于设计更安全的系统提示和权限隔离方案。

**建议动作：** 如果你在开发 Agent 或 RAG 应用，建议阅读原文，了解角色混淆的机制和防御思路。

**为什么重要：** 这是一个典型的“Agent 辅助开发”案例——开发者利用 Claude Code 完成跨平台移植，将原本需要 GPU 的模型变成了浏览器可用的工具。这展示了 Agent 在代码迁移和适配工作中的实际价值。

**建议动作：** 如果你对图像修复或 WebGPU 感兴趣，可以试用在线演示。对于开发者，这个案例展示了如何利用 Agent 加速模型移植工作。

### Dify 1.15.0：新增命令行客户端 difyctl

**背景：** Dify 是一个开源的 LLM 应用开发平台，提供可视化工作流编辑器，用户可以通过 Web UI 构建和运行 AI 应用。

**这次发生了什么：** [6. Dify 1.15.0 发布：新增命令行客户端 difyctl，支持终端驱动工作流](https://github.com/langgenius/dify/releases/tag/1.15.0) 正式发布。核心亮点是新增命令行客户端 **difyctl**，允许用户通过终端直接运行应用和工作流，无需打开 Web UI。此外还改进了引导页、导航、删除确认、工作流编辑器折叠面板和通知提示等 UX/UI 体验。

**具体变化：**
- difyctl 支持 macOS、Linux、Windows 三平台，单命令安装，无需访问令牌。
- 可传递作用域环境变量到 CLI 工具运行。
- 工作流可以被个人 Agent、脚本和 CI 流水线直接调用。

**为什么重要：** difyctl 让 Dify 从“Web 工具”变成了“可编程平台”，大幅提升了自动化集成能力。对于使用 Dify 构建工作流的团队，这意味着可以将工作流嵌入到现有自动化流程中。

**建议动作：** 如果你在使用 Dify，建议升级到 1.15.0 并试用 difyctl。对于需要将 AI 工作流集成到 CI/CD 或自动化脚本中的开发者，这是一个值得关注的功能。

### CrewAI 1.15.0：声明式 Flow、DMN 模式、内联 Crew 定义

**背景：** CrewAI 是一个用于编排多 Agent 工作流的开源框架，开发者可以定义多个 AI Agent 协同完成任务。

**这次发生了什么：** [2. CrewAI 1.15.0 发布：声明式 Flow、DMN 模式、内联 Crew 定义等多项 Agent 工作流增强](https://github.com/crewAIInc/crewAI/releases/tag/1.15.0) 发布。主要新特性包括：

**为什么重要：** 声明式 Flow 和 DMN 模式降低了 Agent 工作流的配置门槛，让非开发者也能定义复杂的多 Agent 协作流程。内联 Crew 定义使编排更灵活。

## 前沿研究观察

### GLM-5.2 本地运行方案

**背景：** GLM-5.2 是 Z.ai 发布的开源模型，744B 参数、40B 活跃参数、1M 上下文窗口，在多项基准测试中与 Claude 4.8 Opus、GPT-5.5、Gemini 3.1 Pro 相当。

**这次发生了什么：** [16. GLM-5.2 – How to Run Locally](https://unsloth.ai/docs/models/glm-5.2) 提供了 GLM-5.2 的本地运行方案，使用 Unsloth 的动态 GGUF 量化技术。2-bit 动态量化（UD-IQ2_M）仅需 239GB 磁盘空间，可运行在 256GB 统一内存的 Mac 上；1-bit 量化仅需 223GB 内存。

**为什么重要：** 744B 参数模型能在单台 Mac 上运行，这得益于高效的量化技术。对于需要本地运行大模型的用户，这是一个值得关注的方案。

**建议动作：** 如果你有高内存 Mac 或服务器，可以尝试运行 GLM-5.2 的量化版本。注意这是研究信号，不等于已经产品化，量化后的性能损失需要自行评估。

**背景：** 见“开源项目 Release 汇总”中的 Krea 2 条目。Krea 2 的技术报告详细介绍了数据筛选原则、模型架构、多阶段训练流程和分布式基础设施。
