### Wayfinder Router：一个不调用模型的确定性查询路由器

[18. Wayfinder Router：实现本地与托管LLM之间确定性路由的开源工具](https://github.com/itsthelore/wayfinder-router) 是一个轻量级 CLI（命令行工具，适合开发者在终端中运行和自动化脚本调用），它的核心思路是：**不调用任何模型来判断一个查询该走本地小模型还是云端大模型**，而是通过分析提示词的结构特征（长度、标题、列表、代码）和可选词汇线索（如“证明”“数学”“硬约束”），在微秒级做出离线路由决策。

**背景与问题**：在多模型工作流中，开发者经常需要把简单查询（如“总结一下”）路由到便宜的本地模型，把复杂查询路由到昂贵的云端模型。现有的路由方案（如 RouteLLM、NotDiamond）依赖调用另一个模型来做判断，这恰恰在旨在节省成本的步骤上增加了延迟、成本和随机性。

**这次发生了什么**：Wayfinder Router 完全离线运行，无需 API 密钥和网络。它默认只使用结构特征进行评分（词汇线索因盲测未泛化而默认关闭），用户可以在自有数据上校准评分阈值。它支持任何 OpenAI 兼容 API（含 Ollama、Anthropic、Groq、vLLM 等），可自托管。

**为什么值得关注**：这个工具把 prompt 路由变成了纯文本分析，对希望节省成本同时保持私密的开发者很实用。但原文也坦诚指出，它在纯语义难题（如一段微妙的代码片段）上表现不佳——这类问题需要语义路由器。**社区讨论，不等于官方确认**，结果可能受测试条件影响。

### 《文明 VI》实测：四大 AI 模型暴露“感知盲区”和“知行差距”

[6. 四大AI对决《文明VI》：Claude核平法国仍输，暴露感知与执行短板](https://aihot.virxact.com/items/cmqx7behn03g3slp0pzrofqz9) 是一个来自英国前首相府数据科学家 Liam Wilkinson 的实验。他搭建了 76 个 MCP（让 Agent 连接外部工具和数据源的协议）工具，将 Claude Opus 4.6、GPT-5.4、Gemini 3.1 Pro 等四个模型放入《文明 VI》进行了 23 场对局。

**背景与问题**：AI Agent 在狭隘任务（修复漏洞、遵循服务策略）上表现越来越好，但现实世界中的决策涉及长链决策、资源分配、不完整信息下的判断。选择题和窄任务测不出这些能力。

**这次发生了什么**：最魔幻的一局是 Claude 扮演葡萄牙。它建起了每回合 200+ 金币的贸易帝国，外交胜利进度 18/20，只差两分就赢了。此时法国的文化胜利进度条飙升，Claude 慌了——它花了 50 回合研发核弹，核平了法国城市图卢兹，但法国最终以外交胜利获胜。Wilkinson 发现两个关键数据：
- **感知盲区**：AI 主动检查全局状态仅占 1-2% 的行动。
- **知行差距**：计划后 10 回合内执行率仅 48-66%。

**为什么重要**：这个实验提供了 AI Agent 在复杂环境中感知与执行差距的实证数据。结论是“智商非瓶颈，感知与执行才是关键”——更聪明的大脑解决不了睁不开眼、伸不出手的问题。**社区讨论，不等于官方确认**，结果可能受测试条件、样本和硬件环境影响。

## 企业应用 / 商业化信号

### CEO-Bench：500 天模拟创业测试，仅 3 个模型盈利

[3. CEO-Bench：仅Claude Fable 5、Claude Opus 4.8和GPT-5.5在500天模拟创业中盈利超过起始资本](https://aihot.virxact.com/items/cmqxnrjtc004ssljh9zvejgbo) 是普林斯顿大学推出的基准测试。它让 AI Agent 在模拟环境中运营一家名为 NovaMind 的订阅软件公司 500 天，起始资金 100 万美元。

**背景与问题**：现有基准测试大多测试窄任务（修复漏洞、对话遵循策略），但现实中的商业决策涉及长链决策、资源分配、不完整信息下的判断。CEO-Bench 专门测试这种“引导智能”。

**这次发生了什么**：14 个测试模型中，仅 Claude Fable 5（最佳轮次盈利 4715 万美元）、Claude Opus 4.8（2780 万美元）和 GPT-5.5（2130 万美元）在最佳运行中超过起始资本。一个**不调用语言模型**的简单规则启发式方法（固定定价、配额和针对性开发）达到 1576 万美元，超越除前三外的所有模型。多数模型无法保持连贯策略，在模拟结束前破产。

**为什么重要**：这个测试直指当前 AI Agent 的致命短板——长期战略决策能力。一个不用 AI 的简单规则系统击败了绝大多数模型，说明“更聪明的大脑”解决不了战略连贯性问题。**待验证**，但该基准的设计思路对评估 Agent 的商业实用性有重要参考价值。

## 算力 / 半导体观察

### DeepSeek 开源 DSpark 推测解码框架

[16. DeepSeek 开源 DSpark 推测解码框架，DeepSeek-V4 单用户生成速度提升 60–85%](https://www.bestblogs.dev/en/article/04ce0133?entry=rss_article_item) 是 DeepSeek 发布的开源推理加速框架。

**背景与问题**：推测解码（speculative decoding）是一种加速大模型推理的技术，通过让一个小模型先“草稿”生成多个 token，再由大模型验证，从而减少大模型的串行生成步骤。但现有方案在负载均衡和草稿质量上仍有优化空间。

**这次发生了什么**：DSpark 采用半自回归草稿生成与负载感知调度，在 DeepSeek-V4-Flash 和 V4-Pro 的生产环境中，单用户生成速度较 MTP-1 基线提升 60–85%，且输出无损。框架包含模型权重与 MIT 许可的 DeepSpec 训练代码。

**为什么重要**：推理速度直接关系到 AI 应用的延迟和成本。DSpark 开源意味着社区可以复现和集成这一加速方案。**待验证**，但数字来自 DeepSeek 官方发布。

[17. AMD Strix Halo RDMA 集群搭建指南发布](https://github.com/kyuz0/amd-strix-halo-vllm-toolboxes/blob/main/rdma_cluster/setup_guide.md) 是 GitHub 用户 kyuz0 发布的社区指南，详细介绍了如何配置两节点 AMD Strix Halo 集群，通过 Intel E810 网卡（RoCE v2）实现 RDMA（远程直接内存访问，用于多节点间高速数据传输）互联，用于分布式 vLLM 推理。

## 前沿研究观察

### 论文 1：Prompt Injection 的带外防御自适应评估

[1. Adaptive Evaluation of Out-of-Band Defenses Against Prompt Injection in LLM Agents](https://arxiv.org/abs/2606.26479) 是一篇 arXiv 论文，研究针对 LLM Agent 的提示注入攻击的带外防御方法。提示注入（prompt injection）是指攻击者通过输入恶意指令，让模型执行非预期操作。带外防御（out-of-band defense）指在模型主推理流程之外增加额外的安全检测层。该论文提出了自适应评估框架来测试这些防御的有效性。

**研究属性**：这是 arXiv 论文，**研究信号不等于产品落地**。原文未给出具体实验结果。

### 论文 2：Instruction Bleed——提示组合 Agent 系统中的跨模块干扰

[2. Instruction Bleed: Cross-Module Interference in Prompt-Composed Agentic Systems](https://arxiv.org/abs/2606.26356) 是一篇 arXiv 论文，研究在由多个提示模块组合而成的 Agent 系统中，不同模块的指令之间可能发生相互干扰（称为“指令泄露”）。例如，一个模块的隐私保护指令可能被另一个模块的指令覆盖或削弱。

**研究属性**：这是 arXiv 论文，**研究信号不等于产品落地**。该问题对多 Agent 系统和复杂工作流设计有潜在影响，但当前仍处于理论分析阶段。

## 今日建议动作

1. **检查你的 Agent 系统是否有“感知盲区”**：参考《文明 VI》实验的发现，检查你的 Agent 是否定期主动获取全局状态，还是只被动响应触发事件。如果 Agent 在复杂环境中运行，建议增加周期性状态检查机制。

2. **试用 Wayfinder Router 做成本优化**：如果你正在使用多模型工作流（本地 + 云端），可以试用 Wayfinder Router 的 `--dry-run` 模式（无需 API 密钥）评估它对查询的难度分类是否匹配你的实际流量。

3. **关注 DeepSeek DSpark 的开源代码**：如果你在部署大模型推理服务，DSpark 的 MIT 许可代码值得研究，尤其是半自回归草稿生成和负载感知调度的实现。

4. **归档 CEO-Bench 的测试方法论**：虽然该基准是研究性质，但其“500 天模拟创业”的设计思路对评估 Agent 的长期战略能力有参考价值，建议存档以备后续参考。

5. **暂时忽略 Grok 4.5 和 GPT-5.6 的早期信号**：这两个都是内部测试或有限合作伙伴访问阶段，公开可用时间未知，普通开发者暂时无需采取行动。

6. **更新 llama.cpp 到最新版本**：如果你在使用 llama.cpp 进行本地推理，b9831 的 DFlash 支持可能带来加速，建议测试后升级。
