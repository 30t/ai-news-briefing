### shot-scraper 1.10：让 Agent 自动录制 Web 操作演示视频

[7. shot-scraper 1.10 发布：新增 video 命令，让 agent 自动录制 Web 操作演示视频](https://simonwillison.net/2026/Jun/30/shot-scraper-video)

**背景：** shot-scraper 是一个基于 Playwright 的 Web 截图和自动化工具，常用于生成网页截图或执行简单的浏览器操作。开发者 Simon Willison 一直在探索如何让编码 Agent 自动产出工作演示。

**这次发生了什么：** 1.10 版本新增了 `video` 命令。用户只需编写一个 `storyboard.yml` 文件，定义一系列操作步骤（如点击、输入、导航），shot-scraper 就会使用 Playwright 录制一段视频，完整记录 Agent 在 Web 应用上的操作过程。

**具体变化：** 作者演示了用该命令录制 Datasette 批量插入 CSV 数据的操作视频，并提供了完整的 YAML 配置示例。该 `storyboard.yml` 文件甚至是由 GPT-5.5 xhigh 在 Codex Desktop 中自动生成的。

**为什么重要：** 这个功能让 Agent 的工作成果从“代码输出”变成了“可视化演示”，对调试、展示和团队协作有直接价值。**建议动作：** 如果你正在构建需要向他人展示的 Agent 工作流，可以试用 shot-scraper 1.10 的 `video` 命令来录制操作演示。

## Agent / 编程工具趋势

### Ornith-1.0：首个“自脚手架”开源编码 Agent 模型

[4. Ornith-1.0发布：基于Gemma 4和Qwen 3.5的自脚手架编码Agent模型，开源且性能领先](https://simonwillison.net/2026/Jun/29/ornith)

**背景：** 大多数编码 Agent 依赖外部框架（如 LangChain、AutoGPT）来管理工具调用循环。Ornith-1.0 是 DeepReinforce 公司发布的第一个模型，它提出了“自脚手架”（self-scaffolding）概念——模型自身就能驱动工具调用循环，不需要外部编排框架。

**这次发生了什么：** Ornith-1.0 基于 Gemma 4（Apache 2.0 许可）和 Qwen 3.5（Apache 2.0 许可）预训练模型，提供 9B Dense、31B Dense、35B MoE 和 397B MoE 四种尺寸，采用 MIT 许可开源。在编码基准测试中，它达到了开源模型中的最佳性能（SOTA）。

**具体变化与证据：** 技术社区博主 Simon Willison 实测了 35B Q4 量化版（约 20GB），在 Datasette 代码库中成功完成了“查找 actor cookie 解码代码”和“查找按钮点击后打开插入对话框的代码”等任务，推理速度达到 103 tokens/s。**注意：** 这是社区实测，不等于官方认证，结果可能受测试环境和硬件影响。

**为什么重要：** 这是首个明确以“自脚手架”为设计目标的编码 Agent 模型，意味着开发者可能不再需要复杂的 Agent 框架就能运行本地编码 Agent。**建议动作：** 如果你对本地运行编码 Agent 感兴趣，可以下载 Ornith-1.0 的 GGUF 量化版在 LM Studio 或 Ollama 中试用。

### Claude Sonnet 5 正式集成 GitHub Copilot

[1. Claude Sonnet 5 正式集成 GitHub Copilot](https://github.blog/changelog/2026-06-30-claude-sonnet-5-is-generally-available-for-github-copilot)

**背景：** GitHub Copilot 是微软旗下最主流的 AI 编程助手，支持在 IDE 和 CLI（命令行工具）中使用多种模型。Claude Sonnet 5 是 Anthropic 最新的 Sonnet 系列模型，定位为性能与速度平衡的编码模型。

**这次发生了什么：** Claude Sonnet 5 现已在 GitHub Copilot 中正式可用。在 GitHub 内部测试中，它在多种编码场景下表现强劲，尤其在 CLI 风格任务上表现突出，同时具备优秀的 prompt-cache 利用率和较低的延迟。

**具体变化：** 该模型按提供商列表价格计费（Usage Based Billing），适用于 Copilot Pro、Pro+、Max、Business 和 Enterprise 用户。企业管理员可通过模型策略设置启用。与其他 Sonnet 模型一样，Claude Sonnet 5 在 Copilot 中采用零数据保留（ZDR）策略。

**为什么重要：** 这是主流 AI 编程工具与前沿模型的直接集成，开发者现在可以在 Copilot 中直接选择 Claude Sonnet 5，无需切换工具。**建议动作：** Copilot 用户可以在模型选择器中查找 Claude Sonnet 5 并试用，注意部署是逐步进行的。

### Anthropic Claude 模型现已在 Azure 上通过 NVIDIA GB300 Blackwell Ultra GPU 提供

[5. Anthropic Claude 模型现已在 Azure 上通过 NVIDIA GB300 Blackwell Ultra GPU 提供](https://blogs.nvidia.com/blog/anthropic-nvidia-gb300-blackwell-ultra-microsoft-azure)

**背景：** Microsoft Foundry 是 Azure 上的 AI 模型部署平台。NVIDIA GB300 Blackwell Ultra 是 NVIDIA 最新的 GPU 架构，GB300 NVL72 系统搭配 Quantum-X800 InfiniBand 网络，专为大规模推理和 Agent 工作负载设计。

**这次发生了什么：** Anthropic 的 Claude 模型现已在 Microsoft Foundry 中正式可用，运行在 Azure 上的 NVIDIA GB300 Blackwell Ultra GPU 上。企业可以通过 Azure 原生服务构建自主 AI Agent。

**具体变化：** NVIDIA 正在与 Anthropic 合作，将 NVIDIA 工具集成到 Anthropic 技术栈中，使 Claude Agent 获得领域特定能力。企业还可以使用 NVIDIA Secure Agent Workspace Reference Design 在 Azure 上运行 Claude Agent。

**为什么重要：** 这标志着顶级模型与最新推理硬件的结合，对关注 AI 基础设施、Agent 部署和云服务的企业用户具有参考价值。**建议动作：** Azure 企业用户可以关注 Microsoft Foundry 中的 Claude 模型可用性，评估其与现有工作流的集成成本。

### IBM Research 发布 ScarfBench：评估 AI Agent 在企业 Java 框架迁移中的能力

[6. IBM Research 发布 ScarfBench：评估 AI Agent 在企业 Java 框架迁移中的能力](https://huggingface.co/blog/ibm-research/scarfbench)

**背景：** 企业 Java 框架迁移（如从 Spring 到 Jakarta EE）是软件开发中最昂贵、最复杂的工程活动之一。现有编码基准测试主要关注 bug 修复和代码生成，但框架迁移需要同时处理代码翻译、行为保持、构建系统适配和运行时依赖。

**这次发生了什么：** IBM Research 发布了 ScarfBench（Self-Contained Application Refactoring Benchmark），这是一个专门评估 AI Agent 在跨框架 Java 迁移任务中能力的开放基准测试。它聚焦于三个主要 Java 生态系统的迁移。

**具体变化：** 与传统的“对比生成代码与参考实现”不同，ScarfBench 评估迁移后的应用是否真正能构建、部署并保持原有行为。原文未提供具体量化结果，但明确了测试场景和评估维度。

**为什么重要：** 企业 Java 框架迁移是实际开发中的痛点，该基准测试为评估和提升 AI Agent 在复杂代码迁移任务中的能力提供了标准化方法。**建议动作：** 从事企业 Java 开发的团队可以关注 ScarfBench 的评估方法，用于测试自己使用的编码 Agent 的迁移能力。

## 前沿研究观察

### 工具增强型 Agent 中的实体绑定失败：一项系统研究

[2. 工具增强型Agent中的实体绑定失败：一项系统研究](https://arxiv.org/abs/2606.30531)

**背景：** 当 Agent 使用工具（如 API 调用、数据库查询）时，通常关注的是“工具是否正确调用”，但一个更隐蔽的问题是：Agent 是否把正确的“实体”（如用户 ID、订单号、文件路径）绑定到了正确的工具参数上？这就是“实体绑定失败”。

**这次发生了什么：** 这篇 arXiv 论文将实体绑定失败定义为独立于工具正确性的可靠性问题，并提出了一个分类法。研究评估了多种实体感知执行机制，包括实体解析前置条件、置信度门控绑定、歧义澄清和溯源追踪。

**具体变化与证据：** 在 60 个任务、5 个模型后端和 6 种工具使用方法上，所有方法均实现了 0% 的错误工具率，但仍产生了错误实体动作。**注意：** 这是 arXiv 论文，属于早期研究信号，不等于已经产品化。

**为什么重要：** 该研究揭示了 Agent 安全与可靠性的一个关键盲点——即使工具调用完全正确，实体绑定错误仍可能导致严重后果（如删除错误用户的数据）。**建议动作：** 如果你在生产环境中构建 Agent 工作流，建议关注实体绑定问题，考虑在关键操作前加入实体确认步骤。

### ToolPrivacyBench：评估工具使用 LLM Agent 的目的绑定隐私

[3. ToolPrivacyBench: Benchmarking Purpose-Bound Privacy in Tool-Using LLM Agents](https://arxiv.org/abs/2606.28061)

**背景：** 当 Agent 使用工具时，可能会将用户数据传递给第三方 API 或服务，引发隐私问题。“目的绑定隐私”指的是数据只能用于用户授权的特定目的，不能超出范围。

**这次发生了什么：** 这篇 arXiv 论文提出了 ToolPrivacyBench，一个用于评估 Agent 在工具使用过程中是否遵守目的绑定隐私的基准测试。**注意：** 这是 arXiv 论文，属于早期研究信号，不等于已经产品化。原文未提供具体量化结果。

**为什么重要：** 随着 Agent 越来越多地调用外部工具和 API，隐私合规成为企业部署的关键障碍。该基准测试为评估 Agent 的隐私保护能力提供了标准化方法。**建议动作：** 关注 Agent 隐私合规的团队可以关注该基准测试的后续发展，但暂时无需采取行动。
