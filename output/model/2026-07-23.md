## 开源项目 Release 汇总

**llama.cpp b10089：CUDA 后端全面支持 k-quant / i-quant / mxfp4 的 GET_ROWS 操作**

[6. llama.cpp b10089：CUDA 后端全面支持k-quant/i-quant/mxfp4的GET_ROWS操作](https://github.com/ggml-org/llama.cpp/releases/tag/b10089)

**背景**：llama.cpp 是一个高性能的 C/C++ 实现，用于在本地（包括 CPU 和 GPU）运行大语言模型，是本地推理领域最活跃的开源项目之一。它使用 GGUF 格式存储量化后的模型权重，其中 k-quant（如 Q4_K_M）和 i-quant 是常见的量化方案，用于在模型大小和推理质量之间取得平衡。

**原来的问题**：在 GPU 上进行推理时，模型中的 embedding 矩阵（如 token_embd）需要执行 GET_ROWS 操作（按行索引查找并返回对应的行向量）。此前，llama.cpp 的 CUDA 后端对 k-quant、i-quant 和 mxfp4 格式的 GET_ROWS 支持不完整，导致这些操作被回退到 CPU 执行。这意味着每次推理都需要将整个 embedding 矩阵从 GPU 拷贝回 CPU，再拷贝回去，严重拖慢推理速度，尤其是在单设备（单 GPU）场景下。

**这次发生了什么**：本次 b10089 版本更新，通过将 dequantize 函数从原有的 dequantize_block 内核中提取为可复用的设备端函数（放在 dequantize.cuh 中），为 CUDA GET_ROWS 操作新增了对以下格式的完整支持：
- **k-quant**：Q2_K 至 Q6_K
- **i-quant**：9 种 i-quant 格式
- **mxfp4**：MXFP4 格式

**具体变化**：现在这些量化格式的 embedding 查找可以直接在 GPU 上完成，不再需要 CPU 回退。原文未明确说明从哪个版本升级而来，但指出此前这些格式的 GET_ROWS 会被后端拒绝，导致调度器回退到主机端。

**为什么重要**：对于使用 llama.cpp 进行本地推理的用户，尤其是使用 Q4_K_M 等常见量化方案的场景，该更新能显著加速 embedding 查找，减少 CPU-GPU 数据传输瓶颈，提升整体推理吞吐。这是对本地推理体验的一次实质性优化。

**建议动作**：如果你正在使用 llama.cpp 进行本地推理，建议升级到 b10089 版本，特别是当你使用 k-quant 或 i-quant 量化模型时，可以预期 embedding 相关操作的性能提升。

**研究问题**：在强化学习（RL）训练中，当使用大规模 rollout（模型生成大量样本）和长上下文时，注意力机制的计算和内存开销巨大。论文提出 DualKV，一种共享提示（shared-prompt）的 Flash Attention 方法，旨在提高 RL 训练效率。

**方法**：DualKV 通过共享多个 rollout 之间的公共提示部分的 Key-Value（KV）缓存，减少重复计算和内存占用。
