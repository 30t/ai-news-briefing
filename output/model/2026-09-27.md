**llama.cpp b11190：修复 LFM2 音频的 mel 预处理器。** 背景是：llama.cpp 是一个用 C/C++ 实现大模型推理的开源项目，支持在本地和多种硬件上运行模型，b 开头的版本号是其滚动构建版本。据 [14. llama.cpp b11190：mtmd: fix mel preprocessor in LFM2 audio (#29403)](https://github.com/ggml-org/llama.cpp/releases/tag/b11190)，本次更新的是 llama.cpp 主项目中的 mtmd（多模态）子模块，针对 LFM2 音频模型的 mel 预处理器（把音频转成模型可读特征的前处理步骤）做了修复。原来的问题是：该预处理器会导致部分音频的贪心转录结果与参考实现不一致——英文测试语句有 4.5%、日文有 6.5% 出现差异，日文中有些差异甚至改变了整个词。具体变化在于：改用 `log(x + 2^-24)` 而不是截断到对数下限，改用对称 Hann 窗（等价于 `torch.hann_window(periodic=False)`），并把归一化 epsilon 加到标准差上而不是放在平方根内；只有 `lfm2a` 预处理器启用这些行为，其他音频预处理器不变。结果或证据：在 200 条 LibriSpeech 英文 test-clean 和 200 条 Common Voice 日文测试语句上，修复后英文 F16 从 191/200 提升到 200/200，日文 F32 从 187/200 提升到 200/200，日文 F16 从 187/200 提升到 199/200（剩余差异是一个逗号）。为什么重要：对使用 llama.cpp 跑 LFM2 音频模型的开发者，这是直接影响转录准确率的修复。建议动作：如果你在用 LFM2 音频做语音转录，建议升级到 b11190 或更高版本并复测你的语料。原文未明确说明从哪个版本升级而来。

**Weights & Biases 分享 Arya 智能体自我改进闭环。** 背景是：Weights & Biases 是一家做机器学习实验跟踪与评估工具的公司，Arya 是其内部智能体。据 [15. GitHub Agentic Autofix 接入 Copilot Memory，用记忆上下文辅助修复安全告警](https://github.blog/changelog/2026-09-25-agentic-autofix-now-uses-copilot-memory)，对已启用 Copilot Memory 的客户，agentic autofix 现在会检索已有记忆以获取有助于解决安全告警的上下文。原来的问题是：Agent 每次修复都从零开始，无法复用之前解决同类问题的经验。具体变化在于：当它创建修复时，会把修复模式存为记忆供未来使用，这些记忆还能帮助 agentic autofix 解决更多安全告警，并让其他 Copilot 功能（如代码审查、云 agent）了解你仓库特有的安全开发模式。结果或证据：原文摘要在此处被截断，未说明具体支持范围、生效条件或版本细节；agentic autofix 和 Copilot Memory 均处于 public preview（公开预览）。为什么重要：它体现了 Agent 工作流与持久记忆结合用于安全修复自动化的方向。建议动作：如果你的团队已启用 Copilot Memory，可以试用并观察记忆是否真的提升修复命中率；注意 public preview 不一定适合生产环境。本条为官方确认。
